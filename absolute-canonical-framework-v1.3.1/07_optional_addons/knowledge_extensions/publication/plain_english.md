# Optional RAG, vector search, and graph database — Plain English
This module answers **Has measured retrieval need justified RAG, vectors, or graph infrastructure?** It applies three canonical rules: RAG, embeddings, vector indexes, and graph databases shall be optional and adopted only when measured scale, retrieval quality, latency, collaboration, or query complexity justifies them.; Retrieval infrastructure shall record source/version, chunking, embedding/model identity, access classification, tests, rebuild triggers, and provenance.; No derived index or embedding may outrank canonical source, bypass confidentiality, or survive invalidation after incompatible source/model changes.
It first checks identity, scope, authority, permission, freshness, and rollback; performs one bounded operation; records evidence and limitations; and reports a truthful state. The key failure is `projection outranks canonical source or leaks restricted content`. The response is to stop the affected action, preserve the finding, restore a safe checkpoint where needed, fix the canonical source, and rerun affected checks. This release remains a candidate pending independent review.

# Optional portfolio, curriculum, notification, designops, and advanced release operations — Plain English
This module answers **Does project scale justify this optional operational layer?** It applies three canonical rules: Portfolio operations, curriculum/learning, notifications, dashboards, DesignOps, FinOps, compliance operations, and advanced release operations shall remain optional modules or enterprise-profile additions.; Each add-on shall declare activation threshold, cost, data/permission boundary, dependencies, canonical state relationship, validation, fallback, and removal path.; Optional add-ons shall not expand the kernel, block minimal-profile operation, or become an independent source of truth.
It first checks identity, scope, authority, permission, freshness, and rollback; performs one bounded operation; records evidence and limitations; and reports a truthful state. The key failure is `add-on creates duplicate authority or excess overhead`. The response is to stop the affected action, preserve the finding, restore a safe checkpoint where needed, fix the canonical source, and rerun affected checks. This release remains a candidate pending independent review.

# Executive Overview
Absolute keeps project work tied to an approved mission and separates builder, reusable framework, and downstream project identities. The kernel governs scope, truth, lifecycle, evidence, change, recovery, modularity, and independent verification. The control plane persists state, work, sessions, decisions, and releases. Capability modules select the smallest healthy permission-bounded tool set. Knowledge modules keep narrative, blueprint, machine, visual, test, graph, and publication representations synchronized. Enforcement rejects invalid state and false completion. Adapters translate host behavior; profiles select scale and policy; optional add-ons remain disabled until measured need justifies them.

The operating loop is: inspect before changing; create one bounded work packet; verify identity, authority, permission, health, and rollback; execute the reversible unit; record evidence and truthful state; update durable registries; run deterministic and semantic checks; checkpoint; perform a second pass; and require a fresh verifier for final exact-hash approval.

In 1.0.0 this loop is executed, not merely specified. The `absolute` runtime permits exactly one next action at any project state, writes every governed mutation into an append-only hash-chained source of truth before touching project state, and binds every observation to the exact tree identity it was computed against. It has no code path that certifies its own output.

# Minimal, standard, enterprise, and downstream profiles — Plain English
This module answers **What is the smallest profile satisfying project scale and risk?** It applies three canonical rules: Minimal, standard, and enterprise profiles shall select bounded module, assurance, documentation, capability, and operational requirements without changing kernel invariants.; A project profile shall declare purpose, applicability, required/optional modules, capabilities, permissions, data classification, gates, installation, validation, migration, and uninstall/rollback.; Profiles shall be composable only through explicit precedence and compatibility checks and shall not import Builder Program history.
It first checks identity, scope, authority, permission, freshness, and rollback; performs one bounded operation; records evidence and limitations; and reports a truthful state. The key failure is `profile silently weakens a mandatory invariant`. The response is to stop the affected action, preserve the finding, restore a safe checkpoint where needed, fix the canonical source, and rerun affected checks. This release remains a candidate pending independent review.

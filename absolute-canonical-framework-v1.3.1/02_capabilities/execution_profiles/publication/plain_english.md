# Provider-independent model and execution routing — Plain English
This module answers **Which execution profile satisfies assurance and data boundaries?** It applies three canonical rules: Kernel routing shall be based on capability, assurance, data sensitivity, irreversibility, context shape, deterministic opportunity, cost, capacity, and health rather than volatile model aliases.; Provider/model names, plans, prices, limits, and host behavior shall live in dated replaceable execution profiles and adapters.; High-risk synthesis and final verification shall use separated roles/contexts, and routing decisions shall record model/tool/version and evidence boundaries.
It first checks identity, scope, authority, permission, freshness, and rollback; performs one bounded operation; records evidence and limitations; and reports a truthful state. The key failure is `routing lowers assurance or violates confidentiality`. The response is to stop the affected action, preserve the finding, restore a safe checkpoint where needed, fix the canonical source, and rerun affected checks. This release remains a candidate pending independent review.

# Manifests, clean releases, checksums, and migration — Plain English
This module answers **Can this package be reproduced, extracted safely, and proven clean?** It applies three canonical rules: A clean release shall be assembled in a fresh staging directory from an explicit allowlist and shall exclude raw sources, chats, history, evidence, caches, credentials, temporary files, and unrelated downstream content.; Every release file shall appear in a manifest with path, bytes, hash, class, source identity, and derivative status; the archive shall be CRC/path checked and re-extracted for hash comparison.; Release, deployment, and production verification shall remain distinct states with migration, rollback, limitations, and compatibility guidance.
It first checks identity, scope, authority, permission, freshness, and rollback; performs one bounded operation; records evidence and limitations; and reports a truthful state. The key failure is `unexpected or unmanifested file enters release`. The response is to stop the affected action, preserve the finding, restore a safe checkpoint where needed, fix the canonical source, and rerun affected checks. This release remains a candidate pending independent review.

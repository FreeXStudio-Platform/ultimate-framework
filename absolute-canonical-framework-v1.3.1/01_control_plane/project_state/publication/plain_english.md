# Canonical project state and atomic updates — Plain English
This module answers **What durable project state should a fresh agent trust?** It applies three canonical rules: Canonical project state shall be schema-validated, versioned, atomically written, conflict-aware, and accompanied by an append-only change journal.; State records shall identify project, framework/profile version, active objective, lifecycle, baseline hashes, permissions, health, and exact next action.; Concurrent actors shall use revision or compare-and-swap controls and may not silently overwrite authoritative state.
It first checks identity, scope, authority, permission, freshness, and rollback; performs one bounded operation; records evidence and limitations; and reports a truthful state. The key failure is `stale or partial write overwrites current state`. The response is to stop the affected action, preserve the finding, restore a safe checkpoint where needed, fix the canonical source, and rerun affected checks. This release remains a candidate pending independent review.

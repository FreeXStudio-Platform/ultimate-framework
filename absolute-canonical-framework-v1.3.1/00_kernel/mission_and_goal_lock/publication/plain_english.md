# Goal lock and mission alignment — Plain English
This module answers **Why is this action allowed, and which approved goal does it advance?** It applies three canonical rules: Every material action shall link to the active mission or to required support, risk reduction, verification, recovery, or maintenance; unrelated work is rejected or deferred.; The control plane shall record the parent goal for each work packet and reject material actions without a valid upward goal link.; Goal-lock checks shall be rerun when scope, project identity, mission, or authority changes.
It first checks identity, scope, authority, permission, freshness, and rollback; performs one bounded operation; records evidence and limitations; and reports a truthful state. The key failure is `unlinked work displaces the mission`. The response is to stop the affected action, preserve the finding, restore a safe checkpoint where needed, fix the canonical source, and rerun affected checks. This release remains a candidate pending independent review.

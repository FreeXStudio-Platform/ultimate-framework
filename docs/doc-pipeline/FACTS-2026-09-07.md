## Regeneration for the NEW layout

The committed `docs/ultimate-engine/REGENERATE.md` assumes the Sep-1 field-trial layout
(`ChatGPT-Framework-Test/{engine,subject}`) and must be rewritten. The working equivalent:

```sh

export ENGINE_HOST_ROOT="$PWD/absolute-canonical-framework-v1.3.0"

( cd absolute-canonical-framework-v1.3.0 \
  && python3 -m tools.docgen.cli index docs/ultimate-engine -o docs/ultimate-engine/DOCS_INDEX.html \
  && python3 -m tools.docgen.cli content-index --docs-root docs/ultimate-engine -o docs/design/doc-system/CONTENT_INDEX.json )

```

Node 26.5.0. Graphviz `dot` 15.1.0.

## Doc-system constraints (engine RULEBOOK L1–L23 + AUTHORING_CONTRACT)

- Every governed document carries the YAML header: `id`, `classification: public`, `title`,
  `surface`, `audience`, `owner`, `status`, `export_allowed: true`, `last_reviewed`, and the
  identity block `version`, `revision`, `produced_by`, `verified_state`.
- Figures are `<!-- figure:ID -->` directives backed by the sibling `<DOC>_spec.json` sidecar.
  Every number in a figure must resolve to a declared `data_sources` entry (L8/L16). Prefer
  numbers **derived** by `scripts/derive_documentation_model.py` over hand-typed ones.
- A planned thing is never written in the present tense. The framework is **internally verified,
  independent certification pending**; gate C20 is `EXTERNAL_HANDOFF_REQUIRED`; no document may
  imply certification.
- Lifecycle (six steps): tag, wire (prefix row in `docs/design/doc-system/DOC_MANIFEST.md`),
  date, **version** (`python3 -m tools.docgen.cli archive cut <doc> --date YYYY-MM-DD` →
  `docs/archive/<id>/vN/`), **changelog** (entry in the payload `CHANGELOG.md` naming the doc),
  **stamp** (`<!-- artifact-hardened: <STATUS> @ <sha> on <date> via <pass> -->`, applied LAST by
  the orchestrator once the body is frozen and Opus has verified it; the sha must be a commit in
  this repository that contains the frozen body).
- Report format: `python3 -m tools.blueprint completeness` renders `blueprint/COMPLETENESS.md`.

## Addendum 5 (14:10) — engine calibration, third site

- The bare-path `git show <sha>:<rel>` defect fixed in `engine/tools/blueprint/completeness.py`
  (Addendum 4) also exists in `engine/tools/corpus_check/guards/stamps.py:190` and
  `engine/tools/corpus_check/guards/identity.py:229`. In this layout (corpus root = payload, one
  level below `.git`) both would report every content-certifying stamp as "not present at <sha>"
  → unverifiable, so a stamped document could never be proven covered. Both now use `./{rel}`.
  Three engine files carry this local calibration; all three are offered upstream as one finding:
  "resolve `git show` paths from the scanned root, not the git top-level".
- Stamp-step order the orchestrator will follow (derived from `archive.py freeze_state`, which
  compares raw bytes, and `identity.body_matches`, which strips stamp lines): set
  `verified_state: verified` (+ `status: approved`) and rebuild → commit A → write
  `<!-- artifact-hardened: Approved @ <A> on 2026-09-07 via three-pass-v1 -->` under each front
  matter → rebuild html/json → delete and re-cut every archive generation so the v1 snapshot
  includes the stamp (header stays `version: 1 / revision: 0`, so the body the stamp certifies is
  unchanged apart from the stamp line) → allowlist `--check` → deep_verify → corpus_check
  `stamps` + `identity` guards → commit B.

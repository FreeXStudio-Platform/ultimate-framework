# Modular architecture, dependencies, interfaces, and repository governance — Plain English
This module answers **Does this rule belong in kernel, module, adapter, profile, or add-on?** It applies three canonical rules: Rules shall be placed by compact-kernel, reusable-module, provider-adapter, project-profile, or optional-add-on tests, with one-way authority and explicit interfaces.; Modules shall declare responsibilities, non-responsibilities, provided/consumed interfaces, dependencies, versions, compatibility, failure, recovery, and ownership.; Repository placement, naming, imports, generated outputs, aliases, deprecation, and migration shall be governed and validated to prevent duplicate control planes.
It first checks identity, scope, authority, permission, freshness, and rollback; performs one bounded operation; records evidence and limitations; and reports a truthful state. The key failure is `provider/project specifics contaminate kernel`. The response is to stop the affected action, preserve the finding, restore a safe checkpoint where needed, fix the canonical source, and rerun affected checks. This release remains a candidate pending independent review.

# Work packets, tasks, dependencies, and progress — Plain English
This module answers **What bounded outcome is being produced under which permissions?** It applies three canonical rules: Every work item shall have stable identity, bounded objective, parent goal, scope, dependencies, permissions, rollback, acceptance criteria, checks, evidence, owner, verifier, and truthful status.; Progress shall be computed only from weighted work that has passed its required verification; planned or implemented-only work shall not count as verified completion.; Duplicate, obsolete, rejected, blocked, deferred, superseded, and rolled-back work shall remain in history with explicit disposition.
It first checks identity, scope, authority, permission, freshness, and rollback; performs one bounded operation; records evidence and limitations; and reports a truthful state. The key failure is `work is marked done before acceptance`. The response is to stop the affected action, preserve the finding, restore a safe checkpoint where needed, fix the canonical source, and rerun affected checks. This release remains a candidate pending independent review.

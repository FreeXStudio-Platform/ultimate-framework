# Runtime execution, rail enforcement, and source-of-truth stamping — Plain English
This module answers **Which single action is permitted right now, and what record proves the last one happened?** It applies three canonical rules: The runtime shall permit exactly one next action at any project state, and shall refuse any command whose rail step is not that action, naming both the refusing rule and the permitted action; Every governed mutation shall be written to the append-only hash-chained source of truth before project state is updated, so that no state can exist without a prior record of the action that produced it; The runtime shall bind every evidence record, gate decision, document seal, and verification result to the exact tree identity it was computed against, and shall treat any record bound to a superseded identity as stale.
It rebuilds what it knows from files every time, refuses any command that is not the one permitted step, writes the artifact and then the chained record and then the state, and marks anything bound to an older identity as stale. The key failure is `a step is skipped and later asserted as done`. The response is to stop the affected action, preserve the finding, restore a safe checkpoint where needed, fix the canonical source, and rerun affected checks.

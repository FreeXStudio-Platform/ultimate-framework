# Lifecycle and two-pass completion — Plain English
This module answers **Which lifecycle state applies, and what permits promotion?** It applies three canonical rules: The framework kernel shall define a provider-independent lifecycle from intake through release and complete, including truthful blocked, failed, recovering, cancelled, stale, and inconclusive routes.; Pass 1 shall construct the complete bounded candidate; Pass 2 shall review the frozen whole, close gaps, optimize without reducing required behavior, and rerun affected checks.; Downstream profiles may refine gate granularity but shall map losslessly to the kernel lifecycle and may not bypass release or evidence gates.
It first checks identity, scope, authority, permission, freshness, and rollback; performs one bounded operation; records evidence and limitations; and reports a truthful state. The key failure is `a moving candidate is treated as verified`. The response is to stop the affected action, preserve the finding, restore a safe checkpoint where needed, fix the canonical source, and rerun affected checks. This release remains a candidate pending independent review.

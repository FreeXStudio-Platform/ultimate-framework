# Positive, negative, adversarial, recovery, and clean-state tests — Plain English
This module answers **Can invalid behavior be rejected and recovery demonstrated?** It applies three canonical rules: Validation shall include positive, negative, boundary, malformed, unavailable, permission-denied, adversarial, mutation, recovery, idempotence, clean-state rebuild, and rollback fixtures as applicable.; Required positive fixtures shall pass and required negative fixtures shall fail in the expected controlled manner; execution without expected behavior is not PASS.; Tests and evaluations shall bind inputs, environment, configuration, dependency versions, outputs, evidence, denominators, and invalidation triggers.
It first checks identity, scope, authority, permission, freshness, and rollback; performs one bounded operation; records evidence and limitations; and reports a truthful state. The key failure is `negative fixture unexpectedly passes`. The response is to stop the affected action, preserve the finding, restore a safe checkpoint where needed, fix the canonical source, and rerun affected checks. This release remains a candidate pending independent review.
